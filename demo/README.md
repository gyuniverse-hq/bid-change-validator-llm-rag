# demo/ — 시연용 가상 자산

> ⚠ **이 디렉터리의 모든 파일은 가상입니다.**
> 실제 나라장터 공고도, 실제 존재하는 업체도 아닙니다.
> 여기 있는 판정 결과를 실제 입찰 판단에 사용하지 마십시오.

## 목적

탐지 성능 측정(그건 `goldenset/`가 담당)이 아니라 **유저와의 상호작용 확인**입니다.

- 프로필에 정보가 있으면 → 코드가 충족/미충족을 판정하는가
- 프로필에 정보가 없으면 → 단정하지 않고 되묻기 질문을 만드는가
- 되묻기에 답을 주면 → 판정이 실제로 갱신되는가

## 실행

```powershell
python main.py demo                              # 프로필 3종 전부 + 되묻기 루프
python main.py demo --profile-name 적격업체       # 특정 프로필만
python main.py demo --no-llm                     # LLM 없이 코드 판정만
python main.py demo --skip-followup              # 되묻기 시뮬레이션 생략
```

## 구성

| 파일 | 내용 |
|---|---|
| `DEMO_공고_스마트도시플랫폼.txt` | 가상 공고 RFP. 확인 필요 조항 4건이 의도적으로 심겨 있음 |
| `profiles/DEMO_적격업체.json` | 모든 요건 충족 — 대부분 `충족`이 나와야 정상 |
| `profiles/DEMO_실적부족업체.json` | 실적 부족 + 지역 불일치 — `미충족`이 나와야 정상 |
| `profiles/DEMO_정보부족업체.json` | 실적·인증 정보 자체가 없음 — `판정 불가 + 되묻기`가 나와야 정상 |
| `run_demo.py` | 실행기. 가상 조달청 API 응답(`DEMO_ITEM`)도 여기 있음 |

## 데모 식별 장치

혼동을 막기 위해 네 겹으로 표시합니다.

1. 파일명 접두어 `DEMO_`
2. 프로필 JSON의 `"_demo": true` 필드
3. 회사명·발주기관명의 `[데모]` 표기, 사업자등록번호는 `000-00-0000X` 형태의 명백한 가짜
4. 리포트 상·하단 배너 — `_demo` 프로필을 쓰면 `main.py analyze`로 돌려도 자동으로 붙음
